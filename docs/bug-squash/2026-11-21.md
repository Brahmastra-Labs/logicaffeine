# Bug squash, 2026-11-21: `logicaffeine_data`

Day 2. The section is `crates/logicaffeine_data`, the CRDTs and the value helpers every execution tier shares
(about 11,000 lines). Two read-only reviews ran in parallel, one on the CRDTs and one on the rest; every finding below
was re-read in the source, and each fix has a test that fails on `main` first.

**Base:** `main` at `d3e7d751`. **Branch:** `bugsquash/2026-11-21-data`.

## Fixed

| # | Where | What went wrong | Fix |
|---|---|---|---|
| 1 | `indexing.rs`, `String` index and `logos_get_char` | The ASCII fast path used the character index as a byte index and only checked that one byte, so after a multi-byte character it returned the wrong one: `"éab"` at 3 gave `"a"`. The interpreter checks the whole text and returned `"b"`. | The fast path holds only when every byte up to the index is ASCII. |
| 2 | `ops.rs`, `logos_approx_eq` | `inf is approximately 1` was true: the tolerance scales with the larger magnitude, which is infinite. Python's `isclose`, which the doc names, says false. Every tier shares this function. | Infinity is approximately only itself. |
| 3 | `ops.rs`, `logos_i64_key_of_f64` | `i64::MAX as f64` rounds up to 2^63, so the float 2^63 matched the Int key `i64::MAX`. | The upper bound is exclusive, at 2^63. |
| 4 | `crdt/delta_buffer.rs`, `deltas_since` | After an eviction, a peer on another replica's line was served the remaining deltas without the evicted one it never saw. | Such a peer gets `None` and falls back to full state. A peer past the evicted delta is still served. |
| 5 | `crdt/causal/context.rs`, `DotContext::merge` | Cloud dots the merged clock already covered stayed in the cloud, so two contexts that had seen the same events compared unequal and `observed` counted events twice. | The merge drops cloud dots at or under the merged clock. |
| 6 | `crdt/ormap.rs`, `apply_delta` | An ORMap delta carries the whole state, but applying it skipped the removal step `merge` has, so a key the sender removed survived on the receiver. | `apply_delta` merges the delta's state. |

## For Collin

* **Removals do not travel through delta sync** for ORSet, ORMap and RGA/YATA: `remove` does not advance `version()`,
  so `delta_since(last_synced)` returns `None` and the receiver keeps the element until a full merge.
  `test_orset_delta_remove` falls back to `merge` for this. Shipping removals needs the delta to carry removed dots
  (or tombstones) and the version to move on remove, which is a protocol change.
* **RemoveWins ORSet merge is not associative.** A removal is inferred from an empty entry, and that inference changes
  with merge order (three replicas, one remove, one concurrent add, give different sets in different orders). It
  needs removals recorded explicitly.
* **`LWWRegister` ties depend on merge direction**: `("x", 5)` and `("y", 5)` swap values. A value tie-break needs
  `T: Ord`, which `LastWriteWins of Real` (an `f64`) does not have; `LatestWrite` already breaks ties correctly.
* **`pow(x, n)` truncates `n` with `as u32` / `as i32`** in both `LogosValue::power` and the interpreter, so
  `pow(0.5, 4294967296)` is 1. The `**` operator already refuses it with `try_from`; both `pow`s should match it.
* **`RGA`/`YATA` `insert_after` past the end** inserts at the head instead of refusing.
* **`read_uvarint`** (`wire.rs`, and `marshal.rs`, which must stay identical) accepts a 10th byte above 1 and drops
  its bits where the doc promises `None`.
